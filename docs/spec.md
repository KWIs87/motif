# Motif — product spec

Owner: Kirk Isham. Personal use, one Spotify Premium account, Android only.
Wireframes (source of truth for layout): https://claude.ai/artifact/9Ub5hBHd5zAiG92wTZwdSu
Last revised: 2026-11-01 (0.12).

## 1. Architecture

| Piece | Role |
|---|---|
| Motif app | All UI. Reads the library through the Spotify Web API; drives playback through the Spotify App Remote SDK. |
| Spotify app | Must stay installed. Decodes and plays audio; Motif never touches the audio stream. |
| Home screen widget | Standard Android app widget, 4x2 default, resizable. Sends the same playback commands. |
| GitHub Actions | Builds and signs every push to `main`; APK lands on the rolling `latest` release. |

Spotify app registration: Development mode, client ID `9343a80fdf824a4e8c1b896312207ff0`, redirect `motif://callback`, package `com.kirkisham.motif`. The release key SHA-1 is registered under Android packages in the Spotify dashboard.

Outside data (all free keys, supplied as BuildConfig fields):

| Need | Source |
|---|---|
| Genre tags, similar artists, artist bios | Last.fm |
| Song credits | Genius (plus Discogs, no key) |
| Synced lyrics | LRCLIB (no key) |
| BPM / key | GetSongBPM (key pending; BPM sort is Build 2) |
| Artist facts | Wikidata, MusicBrainz (no key) |
| Concerts near the user | Ticketmaster Discovery API |

Known constraint: Spotify removed audio-features (BPM), recommendations and offline-download endpoints for new developer apps in Nov 2024. In Feb 2026 it changed Development Mode further: playlist contents moved from `/playlists/{id}/tracks` to `/playlists/{id}/items` (rows carry `item`, not `track`; the playlist object's `tracks` field is now `items`), playlist creation is `POST /me/playlists`, saving and removing library items (including unfollowing a playlist) goes through `PUT`/`DELETE /me/library` with URIs, the batch `GET /tracks?ids=` style endpoints are gone (one `GET /tracks/{id}` per item), search returns at most 10 per page, and playlist contents are only returned for playlists the user owns or collaborates on. Motif uses the Feb 2026 forms (0.8.1). Verify any new endpoint against the current developer-mode list before building on it.

## 2. Design rules

- Dark only. Ground `#121212`, surface `#1A1A1A`, hairline `#1E1E1E`, text `#E8E6E1`, muted `#8A8882`, accent `#C9A96E`.
- Typeface: Inter (system fallback). Weights 300/400/500 only.
- Minimal, understated. No gradients, no promos, no pop-ups, no video, no social features.
- Touch targets ≥ 44 dp. Section labels 11 sp uppercase muted. Row height 52–64 dp with hairline dividers.
- Icons: thin stroke (1.6 px), no filled icons.
- Appearance settings (text color, background color, text size, border glow color and intensity) apply app-wide. The widget takes the app's text color and accent and has its own per-instance setup (§3.9, 0.12).

## 3. Build 1 scope

### 3.1 Login
PKCE flow (done in skeleton). Custom Tab to Spotify, back via `motif://callback`. Tokens in encrypted prefs. Silent refresh.

### 3.2 Playback (App Remote)
- Connect on app start if Spotify is installed; show a one-line prompt if it is not.
- Commands: play URI (track, playlist, episode), pause, resume, next, previous, seek, shuffle, repeat, add to queue.
- Player state stream drives Now playing and the widget.
- Podcasts: back/next are 15-second skips, not episode skips.

### 3.3 Home
- Header: Motif wordmark, star icon (Claude sheet — Build 2, show nothing yet), clock icon (Alarm), gear (Settings — Build 2, basic appearance only in Build 1).
- Pinned playlists at top. Below them, the playlist played most recently moves to the top.
- "All playlists" row. "Podcasts" row. Most recent podcast episode row with resume.
- Mini player at the bottom: art, title, artist, play/pause; swipe left skips. Since 0.10 it is one shared ribbon on every screen except Now playing: art, "Song · Artist" on one line, speaker (Connect devices), plus, play/pause.
- Long press a playlist: Pin/Unpin, Play, Shuffle, Rename, Delete (Delete confirms).

### 3.4 All playlists
Every playlist, pinned first. Sort by Recent, Name, Song count. Same long press menu.

### 3.5 Playlist
- Header: cover, name, count and total length, Play and Shuffle.
- Sort chips: Recent, Name, Artist, Length, Plays (0.11, Last.fm play count), Custom, BPM (BPM chip hidden until Build 2). A second tap on the selected chip flips its direction, Custom included (0.11).
- Custom is the user's own order: long press a song, drag; dropping switches the chip to Custom and writes the order back to Spotify.
- Swipe right on a song: add to playlist (same sheet as the plus button).
- Long press a song: Play next, Add to playlist, Go to artist, Go to album (0.9), Remove from this playlist.
- 3-dot menu: Mass edit (Build 2), Rename, Delete.

### 3.5a Album (0.9)
Not on the wireframe canvas; the owner asked for it explicitly ("when you go to an artist it should also show their albums, EPs, other releases, and all other music with other artists they were a part of"), so it is in scope. Reached from the discography rows on Song and artist info and from "Go to album" in the song menu. The Playlist screen's look without sort chips or drag: header with cover, title, artists (tap opens the artist), year, type (Album / EP / Single / Compilation), song count and length, Play and Shuffle; rows are the songs in album order. Tap plays the song inside the album, long press opens the song menu, swipe right or plus adds to a playlist. Mini player at the bottom.

### 3.5b Person (0.10)
Not on the wireframe canvas; the owner asked for it. Reached from a credit row on Song and artist info (route `person/{name}`, carrying the Discogs or Genius artist id when the credit had one). Header with the name. "About": the Wikipedia summary found through MusicBrainz → Wikidata → enwiki (a name match is required; no first-hit fallback), else the Discogs artist profile; a link out reads "Read on Wikipedia" or "Discogs". "Credited on": what they actually worked on — Genius artist songs when the credit came from Genius and a token exists, else the Discogs artist's releases (`GET /artists/{id}/releases`, newest first, 25) — each matched to Spotify where possible: a matched song plays on tap (plus / long-press plus as elsewhere), a matched release opens the Album screen, unmatched rows stay as text. Then, under a hairline and clearly labelled "Recommendations · Similar listening, not their work", the top song of each Last.fm similar artist, only when Last.fm knows the name without autocorrection. Lookups are cached 24 h.

### 3.5c Genre (0.10)
Not on the wireframe canvas; the owner asked for it. Reached by tapping a tag chip under Credits (route `genre/{tag}`). Title is the tag. "Top artists": a horizontal row of Last.fm `tag.getTopArtists` (50) matched to Spotify artists, tap opens the artist's info. "Top tracks": Last.fm `tag.getTopTracks` (50) matched to Spotify, tap plays, plus adds, long press on the plus makes a new playlist, long press on the row opens the song menu. Only what Spotify matched is shown; rows appear in batches of eight as they match. Cached 24 h.

### 3.6 Now playing (song)
- Art fills the top. Tap art → Song and artist info (Build 2; no-op in Build 1).
- Title, artist. Under them (0.12) a fixed-height album block in small muted text: "Album · 2019 · track 4 of 12" (the album name opens the Album screen), "1.2M plays · 98K listeners" from Last.fm when known, and the tag chips (filtered as on Song and artist info) in one sideways-scrolling row, each opening the Genre screen. The block keeps its height while the lines load, so the scrubber and controls never move; it does not change when lyrics are showing.
- Scrubber with elapsed/remaining.
- Controls: previous, play/pause, next. Plus button beside them: short press shows the 3 playlists most recently added to; long press opens a new-playlist name field.
- Lyrics button: swaps the art for synced lyrics from LRCLIB, current line highlighted, auto-scroll; tap again returns the art. Hidden when LRCLIB has no match. (This is the sing-along feature; full karaoke mode is parked.)
- Share: WhatsApp and SMS only, via Android share sheet filtered to those two.

### 3.7 Now playing (podcast)
Same layout; back/next are 15 s skips; plus button hidden; speed chip cycles 1x / 1.25x / 1.5x / 2x remembered per show; sleep chip takes minutes and counts down.

### 3.8 Alarm
Reached from the clock icon on Home. Since 0.12 it is two screens: the Alarms list and the alarm editor.

**Alarms list** (route `alarms`): TopBar "Alarms" with a plus (hidden while there are no alarms). One row per alarm: the time large, "Name · repeat" muted ("Mon–Fri", "Every day", "Sat, Sun", "Once · Nov 3"), a 44 dp on/off switch. "Rings in 10 h 14 min" in the accent under the alarm that rings next. Tap a row to edit; long press removes it with the Undo pill. Empty state: a centered "Add alarm" pill. Under the list:
- Permissions block, shown only while something is missing, re-checked on resume and every 3 s: four hairline rows — Notifications, Exact alarms, Show over lock screen, Battery exemption — each with a green dot when granted or a muted "Allow" that opens the matching system prompt or page. Notifications are also requested at runtime (Android 13+) on the first visit and on Save.
- "Test alarm": schedules a real one-shot named "Test" for 15 s from now through the normal scheduler, with the first alarm's songs, order, fade and volumes (or the tone when there are none), play-for 3 min; the row reads "Test alarm in 12 s" while it counts down. The test alarm is hidden from the list and removed after it rings.
- "Alarm log": the last 50 fire-path events ("time · event · detail", newest first, "Clear"): scheduled, receiver fired, service started, foreground ok, remote connected / failed with reason, remote playing, tone fallback started, ringing shown, dismissed, snoozed, play-for ended, reschedule, error. It carries alarm ids (six characters), times and failure reasons only — never tokens, keys or anything from the library.

**Editor** (`alarm/{id}`, `alarm/new`; TopBar "Edit alarm" / "New alarm", Save returns to the list). Each alarm is its own object:
- Name (required), time, repeat: One time (a date; with none picked it rings at the next occurrence of the time, today if still ahead) or Recurring (days of week). Time is typed on an inline keypad under the big time (0.11): digits fill right to left like a phone dialer (6, 3, 0 → 6:30; 1, 2, 1, 5 → 12:15), partials are clamped (hour ≤ 12, minutes ≤ 59), AM/PM key, backspace, "Rings in" updates live; the keypad is open for a new alarm, opens on tap when editing, and closes on Done or a press anywhere else. No dialogs.
- Songs: the alarm's own short list, not linked to a playlist. Plus adds from search or from any playlist. Drag to reorder, x to remove. Header shows count and total length.
- Order: Start to end / Repeat first song / Random start.
- Fade in: slider in seconds, 0 to the length of the first song. Ramps the media stream volume linearly from Start volume to End volume (both 0–100 %).
- Play for: 5 / 10 / 20 min / Until dismissed; default 10 min; long press a chip to type minutes. The song list loops if shorter than the window. At the end: stop and go silent.
- Snooze length: 5 / 10 / 15 min.

Ringing screen: full-screen over the lock screen, screen stays on. Shows time, date, alarm name, fade progress, current song x of y, time left, previous/next within the list, large Snooze, small Dismiss. **Either volume button = snooze** while the ringing screen is in front (intercept key events; do not change volume). Dismiss is on screen only. Power button is not used.

Implementation notes: `AlarmManager.setAlarmClock` (exact, survives Doze); the receiver holds a partial wake lock until the foreground service (mediaPlayback type, started within the receiver) has its own; the service owns the ramp and the stop timer and posts a HIGH-importance, CATEGORY_ALARM notification with a full-screen intent to the ringing activity; if App Remote has not reported playback within 8 s of alarm time, a generated tone plays on the alarm stream (never below volume index 1) with the same ramp, so the alarm still wakes the user.

### 3.9 Widget
4x2 default, resizable. Since 0.12 the card is `#121212` with 14 dp corners at the configured transparency and holds four rows: title (medium weight, one line, ellipsized); "Artist · Album" muted (show and episode for podcasts); elapsed · a 3 dp hairline progress bar in the gold accent · remaining; and centred previous / play-pause / next as thin outlined glyphs — previous/next are a bar plus an outlined triangle, play/pause is an outlined rounded square (stroke 2.5, radius 10) holding pause bars or a play triangle. No circles, no plus, no glow. Text follows the app's Appearance text color. Tapping the text opens Now playing. The bar moves once a second while something plays and the app process is alive; otherwise it catches up at the next state change.

Widget setup (shown when the widget is placed, from the launcher's long-press Settings, and by tapping the art thumbnail when it is on), stored per widget instance: Show album line (on; off leaves the artist alone on line 2), Show times (on), Background transparency 0 / 25 / 50 / 75 %, Text size S / M / L, Show art thumbnail at left (off; 40 dp beside the two text lines). Colors are not widget options any more; the "Widget uses app settings" switch is gone from Settings.

### 3.10 Settings (Build 1 subset)
Appearance section (see design rules) and Updates. The rest of the Settings board is Build 2/3.

## 4. Build 2 and later (not now)

- Search screen (box + results). Needed by Alarm's plus button in Build 1 only as a picker; the full screen is Build 2.
- Song and artist info: credits (Genius, Discogs), songs like this (Last.fm → Spotify match), artist facts (Wikidata, MusicBrainz), "Lately" paragraph written by Claude weekly, concerts near you (Ticketmaster). Hide empty sections. Since 0.9 also the artist's discography from Spotify as rows of covers: Albums, Singles & EPs, Compilations, Appears on (each opens the Album screen, §3.5a).

- BPM sort (GetSongBPM) once the key arrives.
- Claude sheet: in-app chat with Spotify tools over the user's library.
- Settings: Improvement report (text + screenshot + log → Claude Code session on this repo → new build), Updates row with Install.
- Karaoke mode: projector/cast lyrics screen, queue, karaoke-version swap. Vocal removal from Spotify audio is not possible and is out of scope.
- Offline downloads: not available to developer-mode apps; parked.

## 5. Out of scope, permanently
Social features, video, ads/promos, anything that bypasses the Spotify app for audio.

## Decisions

Choices made while building where the boards or the text left room. Append; do not rewrite.

### Build 1, stage 1 (0.2)
- App Remote connection is one shared object with reference-counted holds: the activity holds it while in front, the alarm service and widget take their own. It reconnects with exponential backoff (1 s → 30 s) while anyone holds it.
- Album art comes through App Remote's ImagesApi (no Web API image round-trips); playlist covers come from the Web API JSON.
- Stage 1 only: tapping a playlist on Home plays it. Stage 2 moves Play into the long-press menu and tapping opens the playlist.

### Build 1, stage 2 (0.3)
- Home header: star (Claude sheet, no-op until Build 2), clock (Alarm), gear (Settings). The board's search icon is Build 2 and is not shown.
- Home lists pinned playlists, then the 6 most recently played of the rest ("Recent"); the full list is one tap away under All playlists.
- "All podcasts" row opens a sheet listing the saved shows (GET /me/shows); tapping a show plays it and Spotify resumes where that show left off. No separate podcasts screen exists in the boards, so none was added.
- "Last episode" on Home is the last episode App Remote reported playing (stored locally). Spotify's recently-played endpoint does not return episodes.
- Playlist screen: long press and release without moving opens the song menu; long press and drag reorders. A drop while sorted by Name/Artist/Length places the song after its new neighbour in Spotify's order and switches the chip to Custom.
- Shuffle on the Playlist header is a thin icon beside the Play circle (the board shows Play only; the text asks for both).
- Song menu has Play next, Add to playlist, Remove from this playlist. "Go to artist" waits for the Song and artist info screen (Build 2).
- Delete (unfollow) confirms in a bottom sheet, not a dialog.
- Now playing scrubber shows elapsed on the left and remaining ("-2:35") on the right, following the text rather than the board's total.
- Share uses the stock Android share sheet with "Title — Artist" and the open.spotify.com link. Filtering the sheet to WhatsApp and SMS only would mean hard-coding package names; left for later.
- Podcast speed uses App Remote's setPodcastPlaybackSpeed, which has fixed steps (0.5/0.8/1/1.2/1.5/2/3). The 1.25x chip sends 1.2x. Speed is remembered per show (the episode's "album" URI from App Remote is the show).
- Sleep timer lives in PlaybackController so it keeps counting when the screen is left; the chip shows minutes left; long press the chip cancels.
- Settings color pickers are a sheet with 16 presets plus R/G/B sliders. Muted/hairline tones are derived from the chosen text and background so contrast steps stay the same.

### Build 1, stage 3 (0.4)
- Alarms live in DataStore as one JSON list (few, small objects); no Room.
- Scheduling: AlarmManager.setAlarmClock per alarm; snooze is a second one-shot PendingIntent on the same id. A receiver reschedules everything after boot, time or time-zone changes, and when the exact-alarm permission changes.
- Ringing: a foreground service (mediaPlayback type) connects App Remote, plays each song as a single-track URI, and advances when Spotify reports the song paused at its end or drifts to another track (autoplay). The ringing screen is launched by the notification's full-screen intent (lock screen) and directly when unlocked.
- Fade ramps STREAM_MUSIC from start to end volume once a second; the user's media and alarm volumes are restored on snooze or dismiss. The fallback tone (Spotify silent for 10 s) is a generated two-note pattern on the alarm stream at end volume; the fade does not apply to it.
- Repeat first song replays songs[0] each time; Random start rotates the list from a random index; the list loops until the play-for window ends.
- One-time alarms switch themselves off after ringing (snooze still fires). Recurring alarms move to the next selected day.
- Saved alarms: tap loads into the editor, long press asks to delete (sheet). Save with no songs is allowed and warns that the tone will ring.
- Permission lines (exact alarms, lock-screen full-screen intent on Android 14+, battery optimization) show as plain accent-colored lines in the editor while not granted; each opens the matching system settings page.
- The song picker is a sheet (search plus browse any playlist) rather than a Search screen, which is Build 2.

### Build 1, stage 4 (0.5)
- Widget is a classic AppWidgetProvider with RemoteViews (no Glance dependency). 4x2 default, resizable down to about 3x1.
- Colors, opacity and glow are applied by tinting two shape drawables (card and a stroke ring) and the glyphs, so any color works without rendering bitmaps. Glow intensity sets the ring's alpha; a blurred halo is not possible in RemoteViews.
- Button taps broadcast to the provider, which connects App Remote if the app is not running (up to 8 s), sends the command, waits for the new state and redraws. While the app or the alarm service is alive, every playback change redraws the widget.
- Tapping the text opens Now playing in the app. Tapping the art opens Widget settings (also reachable from the launcher's reconfigure action on Android 12+ and when the widget is first added).
- Widget settings screen: "Widget uses app settings" switch (shared with Settings), text color, background color, background opacity, text size, glow color, glow intensity. When the switch is on, only opacity comes from the widget's own settings. The app's default #121212 background maps to the widget card tone #1A1A1A.
- Cover art in the widget comes through App Remote's ImagesApi when connected; otherwise the placeholder tone shows.

### Build 2, 0.6 (Search, Mass edit)
- Search is reached from the search icon in the Home header, between the star and the clock (the board shows star, search, gear; the clock was added in Build 1). One GET /search with type=track,artist,playlist,show,episode and market=from_token feeds four sections: Songs (10), Artists (3), Playlists (5), Podcasts (3 shows, then 5 episodes). The board shows Artists; the text asked for Playlists; both are shown. Empty sections are hidden.
- Search rows: tap a song plays it on its own (no context); long press opens the same song menu as Playlist, minus Remove. Tap an artist opens Song and artist info for that artist. Tap a playlist opens the Playlist screen; a playlist outside the library is fetched once (GET /playlists/{id}) and kept for the session. Tap a show plays its newest episode (GET /shows/{id}/episodes?limit=1), falling back to the show URI. Tap an episode plays it.
- The alarm song picker keeps its sheet (spec §3.8) and now calls the same search method with type=track.
- The song menu gained "Go to artist", which opens the first credited artist that has a Spotify id (local files have none, so the item is hidden for them).
- Mass edit opens from the Playlist 3-dot menu (Mass edit, Rename, Delete). Rows: 20 dp checkbox, 36 dp cover, title, "Artist · 3:42", 44 dp drag handle. Drag the handle to reorder (no long press); tap anywhere else to select. Reorders and removes are kept locally and replayed to Spotify in order when Done is tapped (PUT reorder per drag, DELETE per Remove), so Cancel really discards. The bottom bar shows the count, "Add to" (opens the usual add sheet with all selected URIs, adds at once) and "Remove" (red outline, as on the board). Spotify removes by URI, so removing a selected song also removes any duplicate copies of it in the playlist; the local list mirrors that.
- Add to playlist accepts several URIs now (100 per request); the sheet title shows the song name or "N songs".
- Song and artist info exists as a route (info/track/{id}, info/artist/{id}) with the board's header only; the sections are 0.7.

### Build 2, 0.7 (Song and artist info)
- Opened by tapping the art on Now playing (songs only; while lyrics show, the tap does nothing), by "Go to artist" in the song menu, and by an artist row in Search. The route carries only a Spotify id (info/track/{id} or info/artist/{id}); the screen fetches the track and artist from Spotify first, then runs every outside lookup in parallel. Sections appear as data lands; a section with nothing stays hidden, so the screen may be just the header.
- Credits: Genius (GET /search, then /songs/{id}: writers, producers, featured, custom performances) when GENIUS_ACCESS_TOKEN is built in; otherwise Discogs public search by artist + album (falls back to artist + title), credits from the first of up to three releases that lists any, per-track credits included when the tracklist names the song. The main artist is left out of Discogs credits so members and producers stand out. Tapping a credit opens Search with that name.
- Tag chips under Credits come from Last.fm track.getTopTags (padded with artist tags when under three), five at most. The board's BPM chip waits for the GetSongBPM key.
- Songs like this: Last.fm track.getSimilar (up to 8), padded with the top track of each artist.getSimilar artist when under five, each matched on Spotify with a "track: artist:" search and then a plain search; the artist name must match or the first hit is taken. Six rows. In artist mode (Go to artist) the list is the top song of each similar artist. The plus adds straight into the playlist Spotify is playing from (a small line under the list names it); when nothing from a playlist is playing, it opens the add sheet. The board's "Ask Claude for 20 more" button belongs to the Claude sheet and is not built.
- Artist: MusicBrainz artist search (name match, then first hit) gives origin (begin-area, else area) and active years (life-span; "Born 1987" for a person, "1991 to now" for a group); its Wikidata relation gives the entity, whose enwiki sitelink gives the Wikipedia REST summary (bio, up to eight lines, "Read on Wikipedia" opens the page). Members = count of Wikidata "has part" (P527) claims when more than one. Genre = Last.fm artist tags (minus "seen live"), falling back to Spotify's genres. "Lately" is parked; no placeholder.
- Near you: only when TICKETMASTER_API_KEY is built in. A plain accent line asks for coarse location once; the answer is remembered and the line never returns. Position is the newest last-known fix from any provider, else one 8 s network fix. Ticketmaster Discovery events.json with keyword, latlong, radius 100 miles, classificationName=music, kept only when the artist is among the event's attractions or in its name; five rows, "Tickets" opens the event page.
- Every lookup is cached in memory for 24 hours per track or artist (Info.kt); nothing is written to disk. All calls run on Dispatchers.IO with a 10 s timeout; failures only log the source and status code. The User-Agent names the app and repo, as MusicBrainz and Discogs ask.

### Build 2, 0.8 (Settings: Updates)
- The Updates section sits at the bottom of Settings as on the board; the Improvement report section above it is parked and not shown.
- Check: GET api.github.com/repos/KWIs87/motif/releases/tags/latest (public, no token). The newest version is read from the asset named motif-X.Y[.Z]-sha[-unsigned].apk and compared with BuildConfig.VERSION_NAME segment by segment ("0.7" equals "0.7.0"). The release's first notes line ("Build 0.8 from abc1234, date") is the subtitle while an update is offered; otherwise the subtitle says when the last check ran. Checks happen on app start when the last one is older than 6 hours (time kept in DataStore) and whenever the row is tapped.
- Install: DownloadManager fetches motif-latest.apk into the app's external files dir (Download/), with a system download notification; when it completes, a FileProvider URI (authority <applicationId>.files) is handed to the package installer with ACTION_VIEW and application/vnd.android.package-archive. The button reads "Downloading" meanwhile. Failures show as one plain line under the row.
- Debug builds carry the ".debug" suffix in applicationId, so a release APK will not install over one; the phone runs release builds, where this does not arise.

### 0.8.1 (Spotify Feb 2026 API migration)
- Why: every playlist on Home showed "0 songs", opening one showed no songs and adding to a playlist did nothing, because Spotify renamed or removed the Web API endpoints Motif used for Development Mode apps in February 2026 (developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide).
- Endpoints: `GET/POST/PUT/DELETE /playlists/{id}/tracks` are now `/playlists/{id}/items`; the DELETE body field `tracks` is now `items` (array of `{"uri": ...}`); POST body stays `{"uris": [...]}` (100 per request); reorder parameters are unchanged. `POST /users/{id}/playlists` is now `POST /me/playlists`, so Library.create no longer needs the user id. Unfollowing a playlist (Motif's "Delete") is `DELETE /me/library` with the playlist URI instead of `DELETE /playlists/{id}/followers`; `saveToLibrary`/`removeFromLibrary` exist for any URI type. `GET /tracks?ids=` is gone: `SpotifyApi.tracks(ids)` now runs one `GET /tracks/{id}` per id, at most four in flight, cached for the session. Search `limit` is capped at 10 (`SEARCH_MAX`); `searchTracks` pages with `offset` up to 20 for the alarm song picker. `/me/player`, `/me/shows`, `/shows/{id}/episodes`, `/episodes/{id}`, `/artists/{id}` and `/me/playlists` are unchanged.
- Response shapes: `SpPlaylist.items` (total) replaces `tracks`; `itemCount` is null when Spotify did not include the field and `hasItems` says whether it did. Playlist rows are `SpPlaylistItem.item` (track or episode, `type` tells which); the old `track` key is still read as a fallback. `fields=` filters use the new names. Artist `genres` is absent for Dev Mode apps and is treated as empty (Last.fm tags already come first). `GET /me` no longer returns `product`; nothing used it.
- Owned-only limitation: Spotify returns playlist contents only for playlists the user owns or collaborates on. Followed playlists (Spotify's own, other people's) appear on Home and All playlists with no song count, sort last under "Songs", and when opened show one muted line, "Spotify only shares the contents of playlists you own or collaborate on", in place of the list (also in the alarm song picker's browse view). Play and Shuffle still work through App Remote, which plays the playlist URI itself.
- `DELETE /me/library` body shape could not be verified against the reference page (fetch blocked in the build session). The migration guide shows `{"uris": [...]}` in the body for `PUT /me/library`; a third-party client (spotantic) sends `uris` as a comma-separated query parameter for PUT, DELETE and contains, 40 at most. Motif sends the body form first and, if Spotify rejects it, retries with `?uris=`; it logs only which form was accepted (`MotifApi` tag). Check logcat after the first delete and remove the losing branch.

### 0.9 (Artist discography, Album screen)
- Discography: one `GET /artists/{id}/albums?include_groups=album,single,compilation,appears_on&limit=50&market=from_token`, following `next` up to 200 releases, grouped by `album_group` into Albums, Singles & EPs, Compilations and Appears on (features, soundtracks, other artists' releases that credit the artist). ### 0.12 (owner's tally, third round: silent alarm, alarms list, album block, icon, widget)
1. **Why the 0.11 alarm was silent.** Nothing in the 0.11 fire path wrote anything down, so the cause could not be read back from the phone; the reliability work is therefore a log plus every defect found on review. Defects fixed: (a) POST_NOTIFICATIONS was never requested at runtime, so on Android 13+ the foreground notification and its full-screen intent were dropped silently — no banner, no lock-screen ringing screen (the sound path was separate, see below); it is now asked on the Alarms list's first visit and on Save, and shown as a row until granted. (b) `Alarm.blank` set a one-time alarm's date to tomorrow, so "One time" plus a time later today scheduled for tomorrow; the date is now null until picked and `nextTrigger` rolls a past or missing date to the next occurrence of the time. (c) The receiver let its broadcast wake lock lapse before the service's `onCreate` ran; it now holds a 60 s partial wake lock that the service releases once it has its own 2 h lock. (d) `startForeground` and `startForegroundService` were not guarded; any `ForegroundServiceStartNotAllowedException` or notification failure now lands in the log instead of a silent crash, and `ring()` failing before any sound falls through to `emergencyTone()`. (e) The Spotify deadline dropped from 10 s to 8 s and the tone fallback now ramps on the alarm stream (`STREAM_ALARM`, `USAGE_ALARM`), never below volume index 1, with its own `AudioTrack` init check logged; Spotify keeps the media stream. (f) A one-time alarm whose date and time were already past returned no next trigger and was cancelled without a word; it now rolls forward to the next occurrence of its time and the roll is logged. Verified and left as they were: `foregroundServiceType="mediaPlayback"` with `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, HIGH-importance channel, `CATEGORY_ALARM`, full-screen intent, `setAlarmClock`, and `nextTrigger` for weekday sets (0..7 day scan, first future match).
2. **Alarm log.** `AlarmLog` (alarm/AlarmLog.kt): a 50-entry ring buffer in `files/alarm_log.json`, written on one background thread, exposed as a `StateFlow` for the log screen, and mirrored to logcat under `MotifAlarm`. Entries carry the event, a time and a short detail with six characters of the alarm id; never names, songs, tokens or keys.
3. **Alarms list and editor.** Routes `alarms` (list), `alarm/{id}` / `alarm/new` (editor), `alarmlog`. The row shows time at 34 sp light, "Name · repeat" under it, "Rings in" in the accent under the next alarm only, and a 44 dp switch; long press removes with Undo (0.10 `UndoManager`), which saves and reschedules the object on undo. The old Saved alarms section, its Delete sheet and the three accent permission lines left the editor. The permission block is a data class (`AlarmPermissionStatus.read`) re-read on resume and every 3 s (every 1 s while a test alarm counts down); the green dot is the only green in the app (`#5BA55B`), fixed because the palette has none.
4. **Test alarm.** A transient `Alarm` (new `transient` flag, hidden from the list, deleted after it rings unless snoozed) saved to the store and set with `AlarmScheduler.scheduleAt` — the same `setAlarmClock` call as a real alarm, so the receiver, service, notification, Spotify connect, tone fallback and ringing screen are all exercised. Play-for is 3 min and snooze 5 so a forgotten test does not run on.
5. **Album block.** `AlbumBlock` in NowPlayingScreen: one `GET /tracks/{id}` (session-cached in `SpotifyApi`) gives album name and id, year and the new `SpTrack.track_number` with `album.total_tracks`; `Info.playCount` and `Info.tags` run in parallel from the same object. 68 dp fixed height (18 + 16 + 26 dp lines, two 4 dp gaps) inside the weighted title column with a spacer above it, so the scrubber stays put. Chips are 24 dp at 11 sp in one `horizontalScroll` row. Nothing shows for episodes or local files.
6. **Icon.** Sub at the bottom: tweeter r 13 at y −88, mid r 26 at y −30, sub r 44 (core 14, stroke 5) at y +58; the farthest point is still a rail cap (157 units), so the 0.21 scale and the 33 dp safe zone hold (re-rendered with the circle overlaid). `motif-logos/hexfinal.svg` "WITH RAILS" tile updated to match (outside the repo).
7. **Widget.** Still a classic `AppWidgetProvider` with RemoteViews. The layout follows motif-widget/final.html with padding and gaps cut by about 30 % (12 / 8 dp card padding, 12 dp between buttons, weighted spacers either side of the progress row). Progress is a stock horizontal `ProgressBar` (max 1000) with a layer-list drawable (track `#2A2A2A`, clip in the accent); the tick is a `partiallyUpdateAppWidget` carrying only the bar and the two times, once a second, only while `isPlaying` and a widget exists, from `MotifApp`'s scope (so only while the process is alive). Full redraws still happen on uri / paused / art changes and on Appearance changes. Per-instance options are `WidgetConfig` under `widget_cfg_<appWidgetId>` in Prefs, removed in `onDeleted`; `WidgetStyle`, `widgetUsesApp` and the Settings switch are gone. `configuration_optional` was dropped from the provider so the setup screen always shows on placement; `reconfigurable` stays for the launcher's Settings. The art tap now carries the instance id into the setup activity. Compact cells: under 96 dp of height the second line goes, under 72 the progress row too, under 150 dp of width previous/next go. The glyphs are vector drawables traced from the HTML (40- and 48-unit grids, stroke 2.5), tinted with the text color. Marquee was dropped in favour of an end ellipsis: RemoteViews cannot select the view, so a marquee would only clip.
